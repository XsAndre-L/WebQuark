# Existing sandbox specs A–I

[Implementation sequence](README.md) · [Complete property inventory](api-coverage.md)

These 17 entries compare the playground JSON with component source, generated API tables (including mixin properties), and the component guides. Each entry identifies controls to add, behavioral examples to implement, and the observable result to check. For a tag below, its editor configuration lives at `src/playground/specs/<tag>.sandbox.json` and its public guide at `docs/components/<tag>.md`. The [component index](../components/README.md) links to the guides.

## Shared prerequisites for these examples

1. Render the configured sample data and slot overrides through one path for the editable stage, variant cards and copied examples. Today variant cards apply only variant props, and `slots.default` becomes a named wrapper. Consequently table variants lack rows, comparison variants lack images and many button, card and carousel examples display the original body. Support explicit empty overrides and actual direct slotted elements. Deliberately keep fields omitted where a variant demonstrates a component default.
2. Map property names to the actual HTML attribute, including exceptions such as `formAction` → `formaction`. Escape attribute values, including embedded JSON quotes. Emit direct JS property assignments for arrays/objects/callbacks where the component has no attribute. Show separately the component default, the playground sample value and an unset/inherited value. Optional booleans need an unset choice.
3. Bind the events listed for each component below and display detail in the context of the example that fired it. Treat native events and nested child events separately. Use visible action controls for method demonstrations. Typed JSON editors must retain the previous valid value while showing a parse/shape error. Choose named, prewritten callbacks for callback-only demos.
4. Preserve a single example definition for each scenario. Give each one a concrete starting state, interaction and visible outcome. Exercise selectable values within the editor, and reserve full variant cards for behaviors or combinations that teach something distinct. For fixtures that require a source image, a form or multiple slides, include that dependency in copied examples.
