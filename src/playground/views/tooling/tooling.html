Try the content contract

Read the fictional sample notes and their sample feed JSON. The feed keeps { releases }, Added/Changed/Fixed/Removed summaries and an optional visuals array. A real generator hashes the feed and image bytes and writes a feed-url.ts reference for the application.

wq-changelog version check --config ./changelog.config.ts
wq-changelog notes --config ./changelog.config.ts --include-unreleased

The reviewed configuration declares the project root, manifest, changelog and release paths. Feed generation adds an output directory, public URL prefix and project metadata resolver. Version-only checks require no feed or capture setup. Production settings exclude Unreleased.

Capture setup stays with the application

  1. Register reviewed page profiles or custom scenarios and their required fictional seed facts.
  2. Supply an adapter for an explicitly owned local/demo environment, real authentication, allowed network operations and cleanup evidence.
  3. Install browser binaries explicitly, then stage selected jobs. Lossless WebP is the default; PNG requires an explicit format and matching extension.
  4. Inspect staged images and the report, then publish that reviewed run after provenance, bytes, presentation and cleanup are rechecked.

This static documentation page starts no API, browser automation or database. Release preparation and publication remain separate explicit actions.

See the installed tooling package README for the complete configuration and adapter contracts.
